# 2026-11-17 统计热力图布局优化

本轮从 `5fea950` 的底栏动画优化继续，最终仅调整数据统计页热力图的内部布局。使用 Standard Debug 包、PKG110 / Android 15 真机测试，未修改 R8、页面过渡动画、数据库查询和返回位置逻辑。分类页与专辑封面没有改动。

## 改动与行为验证

原网格使用一层 Row、每周一个 Box、可见周再套 Column，然后放置日期格。新的 `StatsHeatmapGrid.kt` 使用一个 Layout 直接测量和放置可见日期，移除每周的布局容器和空白日期占位布局。周身份使用稳定键，日期格拆为独立的可跳过组合函数；选择另一日期时，只有旧选中和新选中的两个日期格重新执行。

保留了每个真实日期的独立点击节点、测试标签和原有可点击语义，没有将交互压进 Canvas。月份文字、颜色、圆角、选中边框、空白日期位置、默认显示最新月份、横向 ScrollState 以及按年保存的滚动位置均沿用原实现。小数密度下最后一格受固定周高度约束的取整行为也与原实现一致。

验证结果：

- 冻结原网格作为对照，在密度 1、1.25、1.5、2.75、3 和左右两个布局方向下比较像素；包含选择变更、可见范围跳转和数据替换。允许通道差异 0.02、不同像素少于 0.3%，均通过。
- 通过真实 `CompositionTracer` 断言，点击另一日期只执行两个 `StatsHeatmapCell`，点击结果正确。
- 新增反复正反滑动、同时改变页面宽度、替换年份的整页回归，确认日期位置和节点正常。
- 最终生产包上 29 项设备验证通过，覆盖热力图、首次加载和快照返回、统计列表惰性加载、真实封面、主页面过渡、底栏动画像素以及媒体浏览返回位置。日志：[`stats-layout-delivery-tests.log`](../../tmp/stats-layout-delivery-tests.log)。
- 最后补齐原网格对照中的同等测试标签后，4 项网格测试再次通过：[`stats-layout-oracle-tests.log`](../../tmp/stats-layout-oracle-tests.log)。
- `ListeningStatsCalculatorTest` 9 项单元测试通过；Standard Debug 主包和测试包构建成功，`git diff --check` 通过。

## 局部交替采样

测试 APK 同时包含冻结的原网格与新网格，在同一进程中交替首次构建 22 个可见周，每次销毁上个网格，保留真实日期点击组件。执行 40 对采样，每对交替先后顺序，排除前 10 对预热，剩余每版 30 次。测量使用测试边界内的 `System.nanoTime`，未安装 Compose 跟踪器；测量段包含子树 measure，不包含后续 place/draw。

最后一次使用同等测试标签的结果：

| 局部操作 | 原网格中位数 | 新网格中位数 | 原网格 P95 | 新网格 P95 |
| --- | ---: | ---: | ---: | ---: |
| 首次构建组合 | 8.798 ms | 7.424 ms | 12.456 ms | 12.168 ms |
| 子树测量 | 3.438 ms | 2.195 ms | 5.817 ms | 3.630 ms |

局部中位数分别下降约 16% 和 36%，这是该日期网格的观测结果，不能等同于整页或启动加速比例。诊断没有加入耗时阈值断言，以免让系统负载波动变成测试失败。

## 整页对照与剩余问题

原包和候选包均通过 `adb install -r` 安装，不清空数据。最后一组对照使用最终的按周稳定键实现：每轮按“媒体库 → 分类 → 数据统计 → 设置 → 目录”循环五次，每次命令后等待 80 ms。下面为不开跟踪时 gfxinfo 的累计统计及直方图 P95。

| 轮次 | 原包卡顿帧 / 总帧 | 最终包卡顿帧 / 总帧 | 原包 P95 | 最终包 P95 |
| --- | ---: | ---: | ---: | ---: |
| 冷进程后第一轮 | 32/52（61.54%） | 32/52（61.54%） | 650 ms | 700 ms |
| 第二轮 | 37/131（28.24%） | 33/129（25.58%） | 133 ms | 129 ms |
| 第三轮 | 35/161（21.74%） | 31/151（20.53%） | 101 ms | 113 ms |

整体变化较小，P95 不稳定，没有证据表明已明显解决快速切页。另采相同 18 秒 Perfetto 切页轨迹：

| 主线程切片 | 原包总耗时 / 最长 | 最终包总耗时 / 最长 |
| --- | ---: | ---: |
| `Compose:recompose` | 743.86 / 18.55 ms | 736.99 / 21.41 ms |
| `AndroidOwner:measureAndLayout` | 1341.15 / 126.90 ms | 1311.38 / 116.72 ms |
| `Choreographer#doFrame` | 4028.26 / 182.03 ms | 3796.42 / 173.90 ms |

应用 CPU 时间分别约 8.65、8.10 秒；系统媒体提供程序分别约 5.40、3.90 秒，设备负载仍有差异。解析各有 25、29 个负时间戳丢弃事件。轨迹差值只作为记录，不作为稳定百分比收益。

最终包最长布局切片 116.72 ms 中，主线程实际运行 115.62 ms，可运行等待约 0.13 ms，仍有应用自身布局工作需要继续削减。本轮只减少热力图的确定开销，未优化启动流程，也不宣称解决启动卡顿。
